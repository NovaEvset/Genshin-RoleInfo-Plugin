# nonebot-plugin-genshin-role-info

> 原神角色面板 —— NoneBot2 插件
>
> 查询橱窗中角色的面板、圣遗物评分与伤害数据，支持圣遗物适配/推荐与群内排行。

本项目由真寻 Bot 插件
[`zhenxun_plugin_genshin_role_info`](https://github.com/NovaEvset/zhenxun_plugin_genshin_role_info)
v4.3.13 迁移而来，**不依赖真寻 Bot 运行时**，可在标准 NoneBot2 + OneBot v11
环境中以独立插件加载。

## 功能概览

- **角色面板**：读取原神「角色展柜」，渲染包含立绘、属性、天赋、命座、武器、
  五件圣遗物评分与 Miao 兼容伤害表的完整面板图。
- **圣遗物评分**：逐件计算 Miao-Plugin 兼容评分（9 档评级 D/C/B/A/S/SS/SSS/ACE/ACE*），
  汇总为角色总评分，并维护个人与群圣遗物榜单。
- **伤害计算**：内置 Miao-Plugin 兼容引擎，覆盖上游 129 个角色的天赋、武器、
  圣遗物套装、元素反应、月曜/星辉反应与 Buff 规则，输出暴击伤害、期望伤害与
  Buff 说明列表。
- **圣遗物适配与推荐**：按部位或套装给出适配分析；可按评分或**指定伤害项目**
  （末尾加序号）推荐最优搭配。
- **群内排行**：按角色评分或指定伤害项目对群成员排行（最多 16 名）。
- **群最强 / 最菜**：按圣遗物评分记录并播报群内某角色的最强/最菜面板。
- **圣遗物导入**：私聊发送 `good.json`（原神背包扫描结果）以补全圣遗物池。

## 与真寻插件的对应关系

| 方面 | 真寻插件 | 本项目 |
|---|---|---|
| Bot 框架 | 真寻 Bot（基于 NoneBot2 的二次封装） | 标准 NoneBot2 ≥ 2.3 |
| 插件注册 | `__zx_plugin_name__` + `PluginExtraData` + `PluginType` | NoneBot2 原生 `PluginMetadata` |
| 配置 | 真寻配置中心 | `.env` 注入（pydantic 配置类） |
| HTTP 客户端 | `zhenxun.utils.http_utils.AsyncHttpx` | `utils/http_utils.py`（相同方法签名的 httpx 实现） |
| 数据目录 | 真寻 `data` 目录 | 插件包内 `user_data/`，可用环境变量重定向 |
| 定时任务 | `nonebot_plugin_apscheduler` | 同（**可选依赖**，缺失时自动跳过） |
| 米游社同步 | 依赖同仓库 `mys_sign` 插件（扫码登录） | 改为**可选注入**（见[已知限制](#已知限制)） |

**功能等价性**：全部 17 个命令入口、评分算法、伤害引擎、渲染布局与排行逻辑均
按源码逐行迁移。伤害引擎的输出已与源实现做过逐项交叉验证（见[测试](#测试)）。

## 安装

### 方式一：直接克隆到 NoneBot2 插件目录

```bash
cd <你的 NoneBot2 项目>
git clone https://github.com/NovaEvset/Genshin-RoleInfo-Plugin.git \
  nonebot_plugin_genshin_role_info
```

### 方式二：pip 安装

```bash
pip install nonebot-plugin-genshin-role-info
```

### 安装依赖

```bash
pip install nonebot2 nonebot-adapter-onebot httpx Pillow numpy
# 可选：启用每日更新检查
pip install nonebot-plugin-apscheduler
```

> **注意**：本插件自带约 46 MB 内置资源（字体、背景图、伤害规则 JSON）。
> 使用 pip 安装时请确认 `pyproject.toml` 中的 `package-data` 生效，或改用方式一。

## 配置

复制配置模板并按需修改：

```bash
cp .env.example .env
```

### 本插件配置项

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `GENSHIN_ROLE_INFO_DATA_DIR` | 空（用插件包内 `user_data/`） | 用户数据目录：UID 绑定、角色缓存、群榜单、下载的图标 |
| `GENSHIN_ROLE_INFO_API_URLS` | MicroGG + Enka | 橱窗数据接口，逗号分隔按序回退；占位符为位置式 `{}`，也接受 `{uid}` |
| `GENSHIN_ROLE_INFO_REQUEST_TIMEOUT` | `120` | 单次橱窗请求整体超时（秒） |
| `GENSHIN_ROLE_INFO_CHECK_UPDATE` | `true` | 是否启用每日更新检查（需 apscheduler） |
| `GENSHIN_ROLE_INFO_VERSION_URL` | GitHub raw 地址 | 远端版本号检查地址 |
| `GENSHIN_ROLE_INFO_CHANGELOG_URL` | GitHub raw 地址 | 远端更新说明地址 |
| `GENSHIN_ROLE_INFO_MYS_PROVIDER` | 空 | 米游社登录态提供方，格式 `模块:属性`（见[已知限制](#已知限制)） |

### 必需的基础配置

```dotenv
DRIVER=~fastapi
HOST=127.0.0.1
PORT=8080
ONEBOT_WS_URLS=["ws://127.0.0.1:8080/onebot/v11/ws"]

# 无前缀命令匹配（与原插件习惯一致）
COMMAND_START=[""]
```

⚠️ **不要把 `.env` 提交到版本库**（`.gitignore` 已排除）。

## 在 NoneBot2 项目中加载插件

### 自动加载（推荐）

在 `pyproject.toml` 中声明：

```toml
[tool.nonebot]
plugins = ["nonebot_plugin_genshin_role_info"]
```

启动时 `nb run` 会自动发现并加载。

### 手动加载

```python
import nonebot

nonebot.init()
driver = nonebot.get_driver()
driver.register_adapter("nonebot.adapters.onebot.v11", "Adapter")
nonebot.load_plugin("nonebot_plugin_genshin_role_info")
nonebot.run()
```

### 加载成功的标志

日志中应出现（数据目录会随配置变化）：

```
[SUCCESS] nonebot | Succeeded to load plugin "nonebot_plugin_genshin_role_info"
[INFO] nonebot_plugin_genshin_role_info | 原神角色面板: 用户数据目录 /path/to/user_data
```

若未安装 `nonebot-plugin-apscheduler`，会看到一条不影响使用的告警：

```
[WARNING] nonebot_plugin_genshin_role_info | 原神角色面板: 未安装 nonebot-plugin-apscheduler，已跳过每日更新检查调度。
```

## 连接 NapCat

本插件只依赖标准 OneBot v11 协议，因此 NapCat 的**任一**连接方式都可用。
下面给出反向 WebSocket 的推荐配置。

### 1. 启动 NoneBot2

`.env` 中配置：

```dotenv
DRIVER=~fastapi
HOST=127.0.0.1
PORT=8080
ONEBOT_WS_URLS=["ws://127.0.0.1:8080/onebot/v11/ws"]
```

启动后 NoneBot2 会监听 `127.0.0.1:8080`，并在 `/onebot/v11/ws` 提供反向 WS 端点。

### 2. 配置 NapCat

在 NapCat 的 WebUI 中进入「网络配置」，新增一个 **WebSocket 客户端**（反向 WS）：

| 字段 | 值 |
|---|---|
| URL | `ws://127.0.0.1:8080/onebot/v11/ws` |
| 消息格式 | `array`（**必须**，本插件使用消息段数组） |
| 心跳间隔 | `30000`（毫秒，可选） |
| 访问令牌 | 与 NoneBot2 的 `ONEBOT_ACCESS_TOKEN` 保持一致（未设置则留空） |

保存并启用后，NoneBot2 日志应出现：

```
[INFO] nonebot | OneBot V11 | Bot <你的QQ> connected
```

### 3. 关于鉴权

若配置了 `ONEBOT_ACCESS_TOKEN`，OneBot v11 适配器会校验 `Authorization` 头。
反向 WS 还必须携带 `X-Self-ID` 头（适配器强制要求，缺失会以 HTTP 403 拒绝）——
NapCat 会自动附带，无需手工设置。

### 详细说明

#### `原神绑定UID` / `绑定原神UID`

- **语法**：`原神绑定<UID>`、`绑定原神<UID>`
- **必填**：9 位 UID，首位必须为 `1-9`
- **示例**：`原神绑定346948884`
- **限制**：一个 QQ 号只能绑定一个 UID；已绑定需先 `原神解绑`
- **成功响应**：`已成功添加原神uid：346948884`
- **错误响应**：
  - 非纯数字 → `uid/id必须为纯数字！`
  - 格式非法 → `绑定的uid123不合法，请重新绑定!`
  - 已绑定 → `您已绑定过uid：xxx，如果希望更换uid，请先发送原神解绑`

#### `原神解绑`

- **语法**：`原神解绑`
- **成功响应**：`用户数据删除成功...`（未绑定时不回复）

#### `<角色名>面板`

- **语法**：`<角色名>面板`
- **角色名**：支持规范名与别名（如 `胡桃`、`甘雨`、`刻晴`）
- **UID 解析顺序**：
  1. 消息中带 9 位数字 → 用该 UID
  2. 消息中 @ 了某人 → 用被 @ 者绑定的 UID
  3. 否则用发送者绑定的 UID
- **示例**：
  - `甘雨面板`
  - `甘雨面板@某人`
  - `甘雨面板346948884`
- **错误响应**：
  - 未绑定 → `请发送'绑定原神uidxxxx'后再查询！`
  - 角色不在展柜 → `角色展柜里没有<角色名>的信息哦!可查询:<角色列表>`
  - 展柜为空 → 提示在游戏中打开「显示详情」并更新面板

#### `更新原神面板` / `刷新原神面板`

- **语法**：`更新原神面板[UID]`、`刷新原神面板[UID]`
- **参数**：末尾可直接写 9 位 UID；省略则用发送者绑定的 UID
- **示例**：`更新原神面板`、`更新原神面板346948884`
- **冷却**：60 秒（响应形如 `xx秒后可再次更新!`）
- **行为**：重新拉取橱窗数据 → 重算角色评分 → 重建圣遗物榜单与毕业统计 → 生成更新图
- **群内副作用**：会把该玩家的圣遗物榜单合并进群榜单（仅保留评分最高的 20 件）

#### `原神角色排行`

- **语法**：`原神角色排行`
- **行为**：输出该 UID 已缓存角色的更新总览图（按评分/等级/命座/精炼排序）
- **说明**：不发起网络请求，读取本地缓存

#### 圣遗物适配 / 推荐

三类推荐命令共享同一正则：`(.*?)([花羽沙杯冠套])推荐(\d*)$`，即 **`推荐` 前一个
字符必须是 `花`/`羽`/`沙`/`杯`/`冠`/`套`**。

| 形式 | 语法 | 说明 |
|---|---|---|
| 部位适配 | `<角色名><部位>适配` | 展示该部位圣遗物在各角色下的适配评分 |
| 部位推荐 | `<角色名>[属性名]<部位>推荐[序号]` | 从缓存中挑该部位最优圣遗物 |
| 套装推荐 | `<角色名>[套装名]套推荐[序号]` | 挑整套搭配（允许 1 件散件） |
| 独立套推荐 | `<角色名>[属性名]独立套推荐[序号]` | 仅用同套装且未被占用的圣遗物 |

- **可选属性名**：`爆伤`、`暴击`、`精通`、`生命`、`防御`、`攻击`、`火伤`、`冰伤`、
  `雷伤`、`物伤`、`风伤`、`水伤`、`岩伤`、`草伤`、`治疗`、`充能`
- **可选套装名**：取 `artifact.json` 中 5★ 套装名的**前两个字**，如
  `魔女`（炽烈的炎之魔女）、`乐团`（流浪大地的乐团）、`宗室`（昔日宗室之仪）、
  `绝缘`（绝缘之旗印）……
- **可选序号**：正整数，对应角色面板伤害表中**去掉「额外说明」后**的 1-based 项目序号。
  - 不带序号：按**圣遗物评分**排序
  - 带序号：按该项目的**期望伤害**排序
- **示例**：
  - `胡桃冠适配`
  - `胡桃魔女套推荐`
  - `胡桃火伤杯推荐2`
  - `胡桃魔女套推荐2`
  - `胡桃独立套推荐`
- **响应流程**：先发 `正在从圣遗物缓存中匹配伤害最高的宗室套套装搭配，请稍后...`，
  再发结果图；带序号时附带 `目标伤害：2.xxx`
- **错误响应**：
  - 部位无缓存 → `<n>号位没有圣遗物缓存！请先执行'更新面板'指令！`
  - 序号越界 → `伤害序号应在 1-N 之间，当前输入为 M`
  - 无匹配 → `未找到符合条件的圣遗物推荐!`
- **性能提示**：推荐会遍历缓存并反复调用伤害引擎，圣遗物很多时耗时可达数十秒
  （详见[已知限制](#已知限制)）。

#### `<角色名>评分排行` / `<角色名>评分榜单`（仅群聊）

- **语法**：`<角色名>评分排行`、`<角色名>评分榜单`
- **禁止**：带序号（会回复 `评分排行不需要项目序号，请发送：<角色名>评分排行`）
- **行为**：实时读取群成员列表与群名片 → 通过本地 QQ-UID 绑定读取角色缓存 →
  按缓存中的角色评分降序排列，**最多 16 名**
- **说明**：不重新请求 Enka/米游社；未绑定、无角色缓存或未写入评分的成员被跳过
- **无数据响应**：`本群暂无可用于<角色名>评分排行的数据，请群成员先绑定 UID 并更新原神面板。`

#### `<角色名>伤害排行<序号>` / `<角色名>伤害榜单<序号>`（仅群聊）

- **语法**：`<角色名>伤害排行<序号>`，序号从 **1** 开始
- **省略序号**时：回复该角色的伤害项目清单（从群内任一有缓存成员的伤害表提取），
  形如：

  ```
  请指定胡桃伤害面板中的项目序号，例如：胡桃伤害排行1
  各数字对应的伤害项目：
  1. 半血开E重击
  2. 半血开E重击蒸发
  ...
  ```

- **行为**：对每个群成员缓存角色**实时调用伤害引擎**，按该项目期望伤害排序，最多 16 名
- **错误响应**：
  - 序号越界/无数据 → `本群暂无可用于<角色名>第N个伤害项目的排行数据，请确认序号未超出伤害面板范围…`
- **性能提示**：每个群成员一次伤害计算（实测约 10ms/次）。实现已放入线程池，
  不阻塞事件循环，但群成员很多时仍需等待。

#### `最强<角色名>` / `最菜<角色名>` / `群最强XX` / `群最菜XX`（仅群聊）

- **语法**：`最强<角色名>`、`群最强<角色名>`、`最菜<角色名>`、`群最菜<角色名>`
- **行为**：按**圣遗物评分**比较并播报群内已收录的面板图
- **记录时机**：仅在**不带 UID、不带 @** 的群内查询后写入
- **响应示例**：

  ```
  本群最强甘雨!仅根据圣遗物评分评判.
  由'某用户'查询
  <面板图>
  ```

- **无数据响应**：`本群还没有<角色名>的数据收录哦！赶快去查询吧！`
  （最菜额外要求群内至少 2 条记录）
- **附加提示**：查询者面板会参与评比，并可能收到
  `恭喜成为本群最强XX!`、`恭喜你击败@某人成为本群最强XX!`、
  `距本群最强XX还有N分差距!` 等提示

#### `圣遗物榜单` / `圣遗物排行`

- **语法**：`圣遗物榜单`、`圣遗物排行`
- **行为**：展示该 UID 缓存中评分最高的 20 件圣遗物，附大/小毕业统计与最高评分条目
- **UID 解析**：同 `<角色名>面板`
- **错误响应**：
  - 无角色信息 → `未收录任何角色信息,请先进行角色查询!`
  - 无圣遗物 → `未收录任何圣遗物信息,请先输入'更新面板'命令!`

#### `群圣遗物榜单` / `群圣遗物排行`

- **语法**：`群圣遗物榜单`、`群圣遗物排行`
- **行为**：展示本群累计收录的评分最高 20 件圣遗物（带 QQ 头像）
- **错误响应**：`未收录任何圣遗物信息,请先进行查询!`

#### `圣遗物导入`

- **语法**：`圣遗物导入`
- **行为**：返回 `good.json` 的获取步骤说明
- **配套流程**：添加机器人为好友 → 私聊发送 `good.json` 文件

  导入流程会：
  1. 通过 `get_private_file_url` 取文件地址并下载
  2. 落盘为 `player_info/<UID>_artifact.json`
  3. 逐条转换 5★ 20 级圣遗物并去重后写入缓存
  4. 私聊回复 `UIDxxx的缓存圣遗物已导入,本次共导入N个,重复圣遗物M个.`

- **错误响应**：`good.json缺少文件标识，请重新发送。`、
  `good.json读取失败，请重新发送文件后再试。`、`good.json格式不正确，无法导入。`

#### `重置最强<角色名>`（超级用户，仅群聊）

- **语法**：`重置最强<角色名>`
- **权限**：`SUPERUSERS` 中的 QQ
- **行为**：清空本群该角色的最强/最菜记录
- **响应**：`重置群<角色名>成功!`

#### `检查原神面板更新`（超级用户）

- **语法**：`检查原神面板更新`
- **行为**：对比远端版本号与本地 `4.3.13`；有新版本时回复版本与更新内容
- **说明**：无更新时不回复。另有一个每日一次的自动检查（随机 9–22 时），
  需要 `nonebot-plugin-apscheduler`

#### `gsck`（超级用户）

- **语法**：`gsck`
- **行为**：保持与原项目一致的占位实现（仅解析 UID，不做其他操作）。
  保留该命令以确保命令集合与原项目一致。

## 功能详解

### 数据流

```
QQ 用户
  │ 消息事件（OneBot v11）
  ▼
NapCat ──反向 WebSocket──▶ NoneBot2 ──▶ 本插件匹配器
                                          │
              ┌───────────────────────────┼────────────────────────────┐
              ▼                           ▼                            ▼
       本地缓存命中                  MicroGG / Enka                米游社（可选）
   user_data/player_info/         橱窗数据 JSON                需要登录态提供方
        <UID>.json                       │
              │                          ▼
              │                   PlayerInfo 解析
              │                （属性/天赋/命座/武器/圣遗物）
              │                          │
              └──────────────┬───────────┘
                             ▼
                  Miao 兼容评分 + 伤害计算
                             ▼
                  Pillow 渲染面板/榜单/排行图
                             ▼
                  MessageSegment.image ──▶ 回复
```

### 存储布局

```
<GENSHIN_ROLE_INFO_DATA_DIR 或 插件包/user_data>/
├── player_info/
│   ├── qq2uid.json            # QQ → 原神 UID 绑定
│   ├── <UID>.json             # 角色缓存、圣遗物列表/榜单、毕业统计
│   └── <UID>_artifact.json    # 导入的 good.json 原始副本
├── group_info/
│   ├── <群号>.json            # 群圣遗物榜单（前 20）
│   └── <群号>/<角色名>/<评分>-<QQ>.png   # 群最强/最菜面板图
├── res/
│   ├── character/  skill/  talent/  weapon/  reli/  avatar/   # 下载的图标缓存
└── qq_logo/                   # 群榜单用 QQ 头像缓存
```

### 评分与伤害算法

评分与伤害计算均**沿用源项目的算法**，未作改动：

- **圣遗物评分**：`P[x] = 有效权重[x] / 词条成长值[x]`，主词条按 25% 计入，
  按 `align = 66 / (max_mark.total × K) × 100` 归一到「每部位满分 66」；
  评级由 `get_mark_class` 的 9 档阈值决定。
- **伤害计算**：Miao-Plugin 规则表驱动的完整引擎，含抗性三段式、防御系数、
  元素反应（增幅/剧变/月曜/星辉/结晶）、角色与装备 Buff 叠加。

> 该引擎把 Miao 的 JS 规则**转译为 Python 后执行**（`exec`/`eval`）。规则来源为
> 内置 JSON（MIT 许可，见[许可与致谢](#许可与致谢)），请勿将其替换为不可信来源。

### 缓存与更新策略

| 数据 | 缓存位置 | 失效方式 |
|---|---|---|
| 角色橱窗数据 | `player_info/<UID>.json` | 首次查询拉取；`更新原神面板` 强制刷新（60 秒冷却） |
| 图标（立绘/技能/武器/圣遗物） | `res/*/` | 文件存在即复用，缺失时下载并校验 |
| QQ 头像 | `qq_logo/` | 同上 |
| 群最强/最菜 | `group_info/<群号>/<角色名>/` | 新查询比较后替换；`重置最强` 清空 |
| 群圣遗物榜单 | `group_info/<群号>.json` | 每次群内更新面板时合并，保留前 20 |

**HTTP 状态码提示**（与原项目一致）：

| 状态码 | 提示 |
|---|---|
| 400 | `UID 格式错误...` |
| 404 | `玩家不存在（MHY 服务器说的）...` |
| 424 | `查询接口维护中...` |

## 常见问题与排查

<details>
<summary><b>机器人完全没反应</b></summary>

1. 检查 NapCat 是否显示连接成功；NoneBot2 日志应有 `Bot <QQ> connected`。
2. 确认 NapCat 的**消息格式为 `array`**（不是 `string`），否则消息段解析会失败。
3. 确认 `COMMAND_START=[""]`，否则需要加命令前缀。
4. 检查 `block` 与优先级是否被其他插件抢占：日志中会打印
   `Event will be handled by Matcher(...)`。

</details>

<details>
<summary><b>提示「请发送'绑定原神uidxxxx'后再查询！」</b></summary>

该 QQ 尚未绑定 UID，或 @ 的对象未绑定。先发送 `原神绑定<你的UID>`。

</details>

<details>
<summary><b>提示「在游戏中打开显示详情选项!」或「角色展柜里没有X的信息」</b></summary>

原神「角色展柜」只展示 8 个角色，且必须有其他玩家能看到的详情。
进入游戏 → 角色 → 展柜，把想看详情图标的角色放进展柜，然后发送
`更新原神面板`。

</details>

<details>
<summary><b>提示「查询接口维护中...」</b></summary>

MicroGG 接口返回 424。插件会自动回退到 Enka；若两者都不可用，稍后重试即可。
也可通过 `GENSHIN_ROLE_INFO_API_URLS` 调整接口顺序。

</details>

<details>
<summary><b>提示「xx秒后可再次更新!」</b></summary>

更新面板有 60 秒冷却，属原项目既有行为。

</details>

<details>
<summary><b>面板图片缺少立绘或圣遗物图标</b></summary>

图标首次使用时从 enka.network 下载并缓存。若下载失败会提示
`面板图标资源获取失败，请更新原神面板后重试。`。请检查服务器出网能力，
或删除对应缓存目录后重试：

```bash
rm -rf <数据目录>/res/<子目录>
```

</details>

<details>
<summary><b>推荐命令毫无反应</b></summary>

推荐命令要求 `推荐` 前一个字是 `花`/`羽`/`沙`/`杯`/`冠`/`套`。
`胡桃推荐` **不会**匹配，应写成 `胡桃魔女套推荐` 或 `胡桃火伤杯推荐`。

</details>

<details>
<summary><b>提示「未安装 nonebot-plugin-apscheduler」</b></summary>

仅影响每日更新检查。安装 `nonebot-plugin-apscheduler` 或设置
`GENSHIN_ROLE_INFO_CHECK_UPDATE=false` 即可消除。

</details>

<details>
<summary><b>群排行显示「暂无可用于…排行的数据」</b></summary>

排行只读取本地缓存：群成员需先各自绑定 UID 并执行过 `更新原神面板`，
且其角色缓存中包含目标角色。

</details>

<details>
<summary><b>如何定位日志</b></summary>

- 插件加载与数据目录：`[INFO] nonebot_plugin_genshin_role_info`
- 事件与匹配器：`[INFO] nonebot | Event will be handled by Matcher(...)`
- 伤害计算失败：`Miao 伤害条目计算失败 <角色>:<条目>: <原因>`
- 图标下载失败：`原神角色面板: 请求 <url> 失败: <原因>`

</details>

## 已知限制

1. **米游社面板同步为部分实现**
   `米游社更新原神面板` 依赖米游社扫码登录态。原真寻插件使用同仓库的
   `mys_sign` 插件，它不属于标准 NoneBot2 生态，因此本项目改为**约定式注入**：
   设置 `GENSHIN_ROLE_INFO_MYS_PROVIDER=模块:属性` 指向一个提供
   `load_user(qq_id)` 与 `MysAPI()` 的对象即可启用。未配置时该命令返回配置指引。
   数据转换与落盘逻辑（`mys_sync.py`）已完整迁移。

2. **推荐计算耗时较高**
   推荐会遍历圣遗物缓存并反复调用伤害引擎。实测：单件排名约 10ms/候选；
   整套推荐对 5 个「散件位置」各搜索一遍，圣遗物池较大时单次可达数分钟。
   实现已用 `asyncio.to_thread` 避免阻塞事件循环，但请合理预期响应时间。

3. **伤害引擎使用 `exec`/`eval`**
   引擎把内置 JSON 中的 JS 规则转译为 Python 后执行。规则文件当前可信
   （随包分发、MIT 许可），但**若替换为不可信来源则等同于任意代码执行**。

4. **评分算法存在上游遗留的脆弱假设**
   当有效词条权重为空时评分会抛异常（当前 `score.json` 中无此角色）；
   非法副词条名且缺少 `强化次数` 时会触发 `KeyError`。这些路径在当前数据下
   不会触达，测试中已固化其行为。

5. **`重置最强` 保持 `block=False`**
   与原项目一致，因此该命令之后的其他匹配器仍可能继续处理同一消息。

6. **未在真实 QQ + NapCat 上验证**
   当前环境无 QQ 账号与 NapCat 实例。协议层已用等价驱动完成端到端验证
   （见[测试报告](docs/TEST_REPORT.md)）。
